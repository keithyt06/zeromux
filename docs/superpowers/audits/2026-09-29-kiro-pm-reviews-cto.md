## CTO 漏掉的用户价值

1. **醒来路径**:推送 body 带结论(F2)、`last_outcome` 持久化(F1)、离开期间卡(F3)。CTO 通篇在讲「让 agent 跑更多」,没讲「人怎么更快收结果」;北极星「等人时长」没有被任何一项直接改善。
2. **review 闭环**:摘要卡采纳 / 打回(F7)。Kiro 强调「异步 review」,CTO 只给了 verdict 机制,没有给人的操作点。
3. **手机可操作性**:gate、串联、ctl 都是桌面表单或 CLI;需要注明手机上能查看、能停止,不要求能编辑。

## Q1 协调者在手机上怎么看、怎么干预

- **看**:协调者就是一行普通 TriageRow,不设新视图。它派生的子会话在分诊里**按 `parent_id` 折叠在协调者行下**(「↳ 3 个子会话:2 运行 · 1 完成」),点开展开。子会话需要你时照常进入「需要你」(M12 排序不变),行内注明「来自 协调者名」。
- **干预**,由轻到重:① 进入协调者会话直接对话(改方向,最常用);② 子会话行内中断(已有);③ 协调者行 ⋯ →「停止全部子会话」(`sessionActions` 新项,需二次确认);④ `max_sessions` 触顶时推送一次。
- 不做:图形化 DAG、拖拽重派。手机上第一眼能看出的应该是「谁在等我」,而不是「拓扑长什么样」。

## Q2 预检 skipped 的 run 进不进分诊和推送

- **分诊:不进「需要你」**,也不改变已读。gate 通过就意味着「无事发生」,这正是省注意力的目的。只在 F3 离开卡里汇总一行「预检跳过 N 次」,并在定时任务 Sheet 的 run 行显示「gate 通过,未唤醒」。
- **推送:不推送**。现状 overlap skipped 也不推(`scheduled_tasks.rs:1200` 只写 state),保持一致。
- **例外必须报出**:gate 本身超时或无法执行(例如命令不存在),这不是「干净」,应记为 `failed`,并走现有 `run_failed` 推送与分诊「出错」。另外,**连续 N 天全部 skipped** 时在离开卡里提示「任务 X 已 7 天未唤醒」,防止 gate 写错导致永远静默。
